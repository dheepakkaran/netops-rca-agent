3 The pipeline

Six steps from a raw metric to a diagnosis.

01Simulate30 routers, 5 metrics every 10 s, 12 planted faults, 6 decoys
02Kafka65,786 messages on two topics, keyed by router
03Spark Streamingparse, 1-minute features, idempotent writes
04Cassandra64,800 metric rows, 10,800 minute rows, 986 alarm lines
05PyTorch LSTMforecasts normal behaviour; a large miss is an anomaly
06Claude agenttopology, alarm text and runbooks → root router, fault type, next step

Kafka and Cassandra run from their releases on Java 17, without Docker or admin rights.

4 Finding the faults

Every test fault found, with a fifth of the false alarms.

0.94
F1, LSTM forecaster · 8/8 found · 1 false alarm
0.80
F1, rolling z-score · 8/8 found · 5 false alarms

Thresholds were tuned on 4 development faults; the 8 test faults were scored once. Both detect in about 14 seconds. An int8 version is 2.4× smaller with the same detections, but slower on CPU.

5 Naming the root cause

Simple rules miss the quiet faults. The agent did not.

The two faults the rules miss are BGP misconfigurations: the broken router only logs session flaps while its victims lose packets. The agent also dismissed the one noise incident as noise (1/1) and named the fault type in all 9 cases.

6 Model routing

The strongest model only where it changes the answer.

haiku · once · $0.0007

Labeler

Names the 12 alarm clusters as symptom or noise. Checked by code, with Sonnet as a fallback.

sonnet · default

Investigator

Reads the evidence, calls 1–3 read-only tools and submits the diagnosis. Matched Opus on every test incident at 60% lower cost.

opus · escalation

Second opinion

Only when the investigator disagrees with the topology rule: 2 of 9 test incidents, 9/9 correct, $0.13 vs $0.22 for Opus on all.*

* Chosen after seeing the test results, so that cost is computed from the two test runs' logs, not a separate run. 38% of all prompt tokens were cache reads. Every model call in the project cost $0.48 in total.

7 Read before you trust it

What these numbers do not show.

AThe network is simulated: a clean tree of 30 routers, not a real operator mesh.
BThe alarm text is templated, so grouping it was easy (purity 0.999).
COpus and Sonnet both scored 9/9: this test cannot say which model is better, only which is cheaper.
DEight test faults is a small sample.

And four things that broke on the way: a detection score that one giant incident could game, a forecaster that mistook the daily traffic curve for a fault, quantization that made the model smaller but slower, and a confidence score too flat to route on. All eight, with fixes ↗

8 Run it yourself

Java from pixi, Python from uv.

pixi install && uv sync
scripts/services.sh up                     # Kafka + Cassandra
uv run python -m netops.sim                # seeded network
uv run python -m netops.produce            # → Kafka
uv run python -m netops.stream             # Spark → Cassandra
uv run python -m netops.detect             # LSTM vs z-score
uv run python -m netops.agent test routed  # root cause
uv run python -m netops.report             # RESULTS.md
